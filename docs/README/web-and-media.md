# Веб-панель и видео

Веб-панель — дополнительный интерфейс того же процесса бота. У неё общий `Manager`, блокировка физических действий, доступ и предпечатная подготовка. Отключение сайта не требует перехода на другую очередь или переноса заданий.

## Закрытый доступ

Сначала настройте бота и владельца. Участнику нужен общий допуск к принтеру, затем владелец создаёт ему отдельную веб-учётную запись. Отзыв общего допуска закрывает доступ к API и действующим сессиям. Сброс пароля завершает прежние сессии этого аккаунта.

| Настройка | Назначение |
| --- | --- |
| `web_enabled` | Явно включает сервер. По умолчанию выключен. |
| `web_host` / `web_port` | Привязка только к `127.0.0.1`; стандартный порт `3340`. |
| `web_origin` | Полный HTTPS origin, например `https://dashboard.example.com`, без пути. |
| `web_auth_db` | Приватная SQLite-база веб-аккаунтов, сессий и однократных запросов. |
| `web_static_dir` | Каталог `web/` установленной версии. |

Снаружи публикуется HTTPS reverse proxy. Приложение устанавливает cookie с `Secure`, `HttpOnly`, `SameSite=Strict`; изменяющие запросы требуют CSRF-токен. Пароли хранятся как PBKDF2-хеши с индивидуальной солью. API проверяет общий допуск на каждом запросе, а передача приватного файла — также между блоками данных.

Первый аккаунт владельца создаётся на сервере. Задайте `K1C_OWNER_ID` своим числовым `owner_id` из конфигурации бота:

```bash
python3 web_auth.py --db /var/lib/k1c-control/web.sqlite3 \
  --state-db /var/lib/k1c-control/bot.sqlite3 \
  --owner-id "$K1C_OWNER_ID" bootstrap-owner
```

Команда читает JSON с полями `username` и `password` из стандартного ввода. Передайте его из защищённого источника: пароль не должен попадать в аргументы процесса, shell history, Git или общие журналы. База состояния должна принадлежать уже настроенному боту. Указанные пути — пример, их нужно согласовать с установкой.

## Видео

Клиент получает клипы и архив через авторизованный API. Запись выполняет отдельный `media_worker.py` с FFmpeg/ffprobe; она не запускает печать и не меняет макросы принтера.

1. Подготовьте отдельную конфигурацию на основе [примера](../../deploy/media-config.example.json).
2. Задайте URL существующего видеопотока и URL Moonraker, доступные worker.
3. Подготовьте приватный каталог состояния и systemd unit из `deploy/`.
4. Сначала оставьте запись выключенной: `media_capture_enabled=false`.
5. После проверки конфигурации включите запись явно и запустите worker.

Основной процесс использует `media_enabled=true` и тот же `media_state_dir`. Источник задаётся через `media_source_url`; HTTP и RTSP должны соответствовать уже настроенной камере. Репозиторий не меняет её службы.

### Что сохраняется

| Вид | Результат |
| --- | --- |
| Кольцевой буфер | Последние сегменты активного задания; нужны для запроса уже прошедшего интервала. |
| Клип | По умолчанию последние 30 секунд, допустимо 1–300. Результат появляется в архиве; запрос из Telegram может получить ролик в ответ. |
| Таймлапс | Ускоренная запись задания после окончания. Для отменённого или прерванного задания сохраняется соответствующая отметка. |

Длительность относится к записанному времени камеры. При разрывах кадры не выдумываются: метаданные отражают пропуски и доступный интервал. Сразу после запуска буфер может ещё не содержать запрошенную длину.

Архив хранится 7 дней и ограничен 10 GiB. При достижении лимита новые записи приостанавливаются. Владелец может удалять записи; скачивание доступно допущенным пользователям через приложение. nginx не должен иметь `alias` на приватный каталог.

Полное описание инфраструктуры, TLS и миграции — в [deploy/README.txt](../../deploy/README.txt). Перед использованием скриптов прочитайте их аргументы и адаптируйте конфигурацию сервера.
